4 · AI design: how it works

The AI uses only approved content and the employee's own record; it never invents courses, rules or scores

The coach, step by step

1 · Who is asking. Identity comes from SSO. The coach only ever gets this employee's own profile, gaps and plan. The server enforces this, not the prompt.

2 · Guardrail layer 1, before any model call. Rules catch colleague data, pay and promotion, prompt injection, wellbeing and crisis. National ID, phone and email are masked.

3 · Retrieve approved sources. Thai word segmentation plus multilingual embeddings, over lesson text, Thai video transcripts and programme policies.

4 · Layer 2, then the answer. A small model checks intent. The main model answers in the user's language and must cite [S1], [S2]. No source means "I don't have approved material".

5 · Blocked topics get fixed, reviewed replies. These point to the manager or HRBP, the EAP, or the 1323 crisis hotline. They cannot be talked around.

The path engine

  1. Rules shortlist items tagged to each gap's skill and level, with a format mix, within 2 h a month of paid learning time.
  2. The LLM puts them in order and writes a reason for each step, in Thai and English.
  3. A validator checks every item ID exists and every critical gap is covered.
  4. The manager approves. 12,000 paths run overnight through the Batch API, at 50% of the price.

Thai, done properly

  • Thai has no spaces between words, so search needs word segmentation, not plain keywords.
  • Polite register (ค่ะ / นะคะ), Thai-English mixing (SBI, OEE) and a company glossary.
  • Native-speaker review in every eval. On-shore Thai models (Typhoon, ThaiLLM) are an option later for simple tasks.

Built and running in the prototype

5

The core design choice: the model chooses from a menu we control and never writes the menu. The path engine can only order catalogue items that the rules already shortlisted, and its output is checked against real IDs. The coach can only cite approved passages, and the server, not the prompt, decides which personal data it sees.
